# 🚗 AutoJournal

**AutoJournal** — локальное standalone-приложение для ведения журнала автомобиля.

Приложение предназначено для хранения информации об автомобиле, учета расходов, контроля технического обслуживания, создания напоминаний и резервного копирования данных.

Проект разрабатывается на **Go** с использованием **Wails v2** для создания desktop-приложения, **SQLite** для локального хранения данных и **Vue + TypeScript** для пользовательского интерфейса.

## 📌 О проекте

AutoJournal — приложение для владельцев автомобилей, позволяющее хранить всю основную информацию об автомобиле в одном месте.

Вместо использования отдельных заметок, таблиц или бумажных записей пользователь может вести цифровой журнал, содержащий:

* данные автомобиля;
* текущий пробег;
* историю расходов;
* категории расходов;
* информацию о техническом обслуживании;
* напоминания о предстоящих работах;
* фотографии чеков;
* резервные копии базы данных.

Приложение рассчитано на **локальную работу** и не требует постоянного подключения к серверу. Данные хранятся в локальной базе SQLite.

## ✨ Возможности

### 🚘 Профиль автомобиля

Приложение предусматривает хранение основных характеристик автомобиля:

* марка;
* модель;
* год выпуска;
* VIN;
* цвет;
* объем двигателя;
* тип топлива;
* текущий пробег;
* дополнительные заметки.

VIN предполагается проверять на соответствие стандартному формату из 17 символов.

---

### 💰 Учет расходов

Пользователь может регистрировать расходы, связанные с автомобилем.

Для каждого расхода предусмотрены:

* категория;
* сумма;
* валюта;
* дата;
* пробег на момент расхода;
* описание;
* путь к фотографии чека.

Предусмотрена статистика расходов по категориям и периодам, а также расчет среднего расхода на 100 км.

Примеры категорий:

* ⛽ Топливо
* 🔧 Запчасти
* 🛠 Техническое обслуживание
* 🧽 Мойка
* 🛡 Страхование
* 🧰 Ремонт
* 📦 Другое

---

### 🔔 Напоминания

Система позволяет создавать напоминания о техническом обслуживании автомобиля.

Например:

* замена масла;
* замена или перестановка шин;
* страхование;
* плановое техническое обслуживание;
* пользовательские задачи.

Напоминание может зависеть одновременно от:

* даты;
* пробега.

Система учитывает то условие, которое наступает раньше.

---

### 💾 Резервное копирование

Предусмотрено создание локальных резервных копий базы данных.

Резервные копии позволяют восстановить данные в случае повреждения основной базы или переноса данных на другой компьютер.

Для резервного копирования предусмотрена отдельная сущность `backups`, в которой хранится информация о созданных копиях.

---

### 📤 Экспорт

Планируется экспорт информации в:

* CSV;
* JSON.

Для этого используются стандартные библиотеки Go `encoding/csv` и `encoding/json`.

## 🛠 Технологический стек

| Технология                | Назначение                       |
| ------------------------- | -------------------------------- |
| **Go**                    | Backend и основная бизнес-логика |
| **Wails v2**              | Создание desktop-приложения      |
| **SQLite**                | Локальная база данных            |
| **Vue**                   | Пользовательский интерфейс       |
| **TypeScript**            | Frontend-разработка              |
| **SQL**                   | Работа с базой данных            |
| **sqlx**                  | Удобная работа с SQL из Go       |
| **golang-migrate**        | Миграции базы данных             |
| **robfig/cron**           | Планировщик напоминаний          |

Архитектура проекта предусматривает использование `modernc.org/sqlite`, позволяющего работать с SQLite без CGO, а также `sqlx`, `golang-migrate`, `robfig/cron` и `validator`.

## 🏗 Архитектура

Проект построен с разделением на несколько слоев:

```text
┌─────────────────────────────────────┐
│          Vue + TypeScript           │
│              Frontend               │
└──────────────────┬──────────────────┘
                   │
                   │ Wails bindings
                   ▼
┌─────────────────────────────────────┐
│            Handler / App            │
│          Go ↔ JavaScript            │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│              Service                │
│          Бизнес-логика              │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│             Storage                 │
│       Repository + SQLite           │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│              SQLite                 │
│            data.db                  │
└─────────────────────────────────────┘
```

Основной принцип архитектуры заключается в разделении:

* `domain` — бизнес-модели;
* `storage` — работа с базой данных;
* `service` — бизнес-логика;
* `handler` — Wails API;
* `frontend` — пользовательский интерфейс.

## 🔔 Система напоминаний

Напоминания могут срабатывать по двум параметрам:

```text
                Напоминание
                     │
            ┌────────┴────────┐
            │                 │
        По дате            По пробегу
            │                 │
            └────────┬────────┘
                     ▼
              Наступил раньше
                     │
                     ▼
                Уведомление
```

Например:

```text
Замена масла

Каждые:
10 000 км
или
365 дней
```

Если автомобиль проехал 10 000 км раньше наступления года — напоминание появляется по пробегу.

При обновлении одометра система должна пересчитывать ближайшие значения ТО для активных напоминаний.

## 💾 Резервное копирование

Для резервного копирования SQLite предполагается использовать:

```sql
VACUUM INTO 'backup.db';
```

Этот механизм позволяет создавать копию базы данных без необходимости останавливать приложение.

Расположение данных использует системный каталог конфигурации пользователя:

```text
Windows:
%AppData%\autojournal\

macOS:
~/Library/Application Support/autojournal/

Linux:
~/.config/autojournal/
```

Фотографии чеков хранятся в отдельной директории:

```text
receipts/
```

## 🧪 Тестирование

Архитектура проекта предусматривает несколько уровней тестирования.

### Unit-тесты

Основное внимание уделяется бизнес-логике сервисов.

Особенно важна проверка:

```text
ReminderService.CalculateNextDue()
```

поскольку именно эта функция отвечает за расчет следующего срока технического обслуживания.

### Интеграционные тесты

Для проверки SQLite предполагается использовать:

```text
:memory:
```

то есть временную in-memory базу данных.

В рамках тестов выполняются миграции и проверяется работа репозиториев с реальной SQLite БД.
